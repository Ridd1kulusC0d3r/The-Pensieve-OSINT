# Contributing

The goal is a useful analyst second brain, not a landfill of links.

## Canonical source of truth

**Edit knowledge/*.json, not generated exports.**

- knowledge/tools.json is canonical for tools/services.
- data/tools.csv is generated by scripts/build_catalog.py.
- site/data/* is generated for GitHub Pages.

## Add a resource

A useful record includes a stable ID, canonical URL, category, accepted inputs, expected outputs, workflow stage, access model, region, status, at least one meaningful caveat, review date and verification guidance when the result is easy to over-interpret.

## Curation rules

Prefer original/official sources, maintained projects, clear investigative value, reproducible results, documented limitations and sources that can be distinguished from aggregators/copies.

Avoid duplicate mirrors, SEO listicles, abandoned clones when a maintained upstream exists, unclear provenance, resources whose main value is bypassing access controls, unnecessary exposure of personal data, and case-specific sensitive data in public memory.

## Add analyst memory

Patterns in memory/ must be sanitized and reusable.

Use:

- observation;
- possible explanations;
- do not infer;
- useful checks;
- confidence impact.

Never add client/target data, credentials, private screenshots or confidential case evidence.

## Validate before PR

~~~bash
python scripts/validate_knowledge.py
python scripts/build_catalog.py
~~~

The CI also checks documentation links and generated site payloads.

## Pull request description

Explain what changed, why an analyst needs it, where it fits in the workflow, what input/output semantics apply, how the canonical source was verified, and any analytical caveats.
